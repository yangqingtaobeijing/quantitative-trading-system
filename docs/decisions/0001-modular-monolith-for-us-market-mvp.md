# ADR 0001：美股 MVP 采用模块化单体

日期：2026-04-26  
状态：Accepted  

## 背景

系统长期目标包括数据、策略、回测、模拟盘、实盘、风控和工作台。第一阶段只有个人使用和美股日线策略闭环，不需要分布式部署。

## 决策

第一阶段采用 Python 模块化单体：

1. 核心逻辑拆成明确包边界。
2. 所有包在一个代码仓库中开发和测试。
3. 暂不引入微服务、消息队列和容器编排。
4. 券商和数据源通过接口隔离，后续可以替换。

## 理由

1. 减少初期运维和部署复杂度。
2. 方便快速验证交易核心逻辑。
3. 避免在需求未稳定前引入过重架构。
4. 模块边界清晰，后续仍可拆分服务。

## 后果

正面：

1. 开发速度快。
2. 本地测试简单。
3. 交易核心逻辑更容易统一验证。

负面：

1. 多账户、多策略并发扩展能力有限。
2. 实盘阶段需要进一步增强任务调度、监控和恢复。
3. 前后端和后台任务边界后续需要更正式的部署方案。

## 复审条件

出现以下情况时重新评估架构：

1. 需要多账户并发实盘。
2. 需要分钟线或更高频实盘。
3. 需要云端长期运行和多用户权限。
4. 回测任务需要分布式计算。
